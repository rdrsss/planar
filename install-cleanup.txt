# install-cleanup.txt — artifacts that older Planar versions installed into
# $PLANAR_HOME but current Planar no longer ships. On every run, install.sh
# removes each listed path (if present) so a re-install over an old tree is
# clean: `cmake --install` overwrites the targets it builds but never
# deletes files left behind by a prior install.
#
# Format: one path per line, RELATIVE to $PLANAR_HOME. Blank lines and lines
# starting with `#` are ignored; an inline `# note` is stripped. A trailing
# slash means "directory" (removed with `rm -rf`); otherwise it's a file
# (removed with `rm -f`). Paths must not contain spaces.
#
# When you remove something Planar used to install under $PLANAR_HOME, add it
# here with a short why/when note. (Old copies and symlinks that earlier
# installs put OUTSIDE $PLANAR_HOME, such as ~/.claude/commands/ links, unprefixed
# agent links and pl-* skill directories, are removed by install.sh's sweep
# "Retiring the previous skill and agent projections", not by this manifest.)
#
# (No active entries. `bin/planar-execute` was listed here when the Lua harness
# was extracted to a separate external project (2026-06); plan 633 revived
# planar-execute as a shipped fifth binary — the deterministic spawn-free
# workflow engine — so the cleanup line was removed (a re-install must keep,
# not delete, it).)
# The retired agent.db (plan 1089) is NOT listed here: it is data, and
# removing it needs the live-queue guard and the old-range checks, so the
# installer's retire step (scripts/install-lib/queue-retire.sh,
# queue_retire_store) removes agent.db, its -wal/-shm and the old numbered
# queue logs instead.
# Retired Python-wheel Mt-KaHyPar bridge (decision 1006, task 6460): the
# `--with-mtkahypar` flag installed these; the solver is now vendored from
# source and linked directly into the C++ tree (opt-in via
# -DPLANAR_WITH_MTKAHYPAR=ON), so a wheel environment and its launcher are
# dead weight from any prior install.
bin/mtkahypar
opt/mtkahypar/
# Retired vendored Mt-KaHyPar shared library (decision 1293): installs built
# with `install.sh --with-solver` put the solver's dynamic library here. Master
# no longer builds, links or installs it (the solver arm lives on branch
# `dev/grouping-solvers`), so a re-install removes it.
lib/libmtkahypar.dylib

# NOT listed: templates/doc-prompts/{adr_index,changelog,feature,getting_started,
# glossary,research}.md and any other renamed or formerly shipped template.
# templates/ is a data path: an install places shipped defaults missing-only,
# even with --force, and never removes or overwrites a template, so a cleanup
# line naming one could only mislead (the installer skips it and says so).
